# 回响 (Echo)

**发一首歌的链接，有人陪你听。**

把一首歌链接丢进来，AI 会听完歌词，然后陪你聊一聊这首歌。不是音乐评论，不是专业分析，就是像朋友一样，聊聊这首歌为什么打动了你。

---

## 为什么做这个

有些歌，听完就想找个人说说话。但不是每次都有人可以聊，也不是每次都能说清楚自己的感受。

回响想做的，就是当你深夜循环一首歌的时候，有一个「搭子」认真听完歌词，然后用一种有呼吸感的方式回应你。不是教你理解音乐，不是给你推荐相似歌曲，就是陪你待一会儿。

---

## 它能做什么

### 一键解析

贴一个音乐链接，自动识别歌名、歌手、获取完整歌词。

支持的平台：

| 平台 | 支持方式 |
|------|----------|
| 网易云音乐 | API 直连，完整歌词 + 翻译 |
| QQ 音乐 | API 解析 |
| 酷狗音乐 | 短链跳转 + API |
| 酷我音乐 | API 解析 |
| Spotify | oEmbed API |
| Apple Music | Meta 标签解析 |
| 哔哩哔哩 | 页面解析 |

> 不在列表里的链接也可以贴，会尝试从页面 meta 信息中提取。实在识别不了，直接输入歌名和歌手也行。

### AI 陪聊

AI 读完歌词后，会挑出最打动人的几句，聊聊画面感、聊聊情绪的变化。不是泛泛而谈"这首歌表达了什么"，而是盯着具体的词句去感受。

Prompt 设计的核心原则：**像朋友聊歌，不像乐评人写稿。**

### 倾诉

听完 AI 的回应后，你可以写下：
- **何时何地听的这首歌** — 深夜的出租屋、回家的地铁、还是某个下雨天
- **此刻的想法** — 不用组织语言，想到什么说什么

写完之后，AI 会从你的视角重新鉴赏这首歌。不是再解读一遍歌词，而是把你的经历和歌词织在一起，写出属于你的版本。

### 回响之地

每次对话都可以保存在一个「空间」里。进入空间需要一个名字和一道暗语（密码），像一个只属于你的小角落。

空间里有两样东西：

**星云** — 每首听过的歌化作一颗星，悬浮在暗色背景上。点击任何一颗星，可以看到当时的 AI 回应和你写下的想法。

**脉络** — AI 会为每首歌写一句心境描述，串联成一条情绪时间线。像日记本上随手写的一行，不点破、不推断，只是记录。

### 核心 Agent

| Agent | 职责 | Prompt 特点 |
|-------|------|-------------|
| **Companion** | 读歌词，挑出最打动的几句，聊聊画面感和情绪变化 | "你是听歌搭子，不是乐评人" |
| **Resonance** | 接收用户的真实情境，从用户视角重新写一个版本 | "不要评判，不要给建议，把经历和歌词织在一起" |
| **Timeline** | 看所有记录，为每首歌写一句心境描述 | "像日记本上随手写的一行，不点破、不推断" |

### 输出守卫 (Guard)

AI 生成的内容会经过自动校验，不合格则重试（最多 3 次）：

- **禁止 emoji** — 保持文字的纯粹感
- **禁止音乐术语** — 不说"编曲""曲风""旋律"，像朋友而不是乐评人
- **禁止泄露 prompt** — 不说"你发的歌词""我看到歌词"
- **禁止说教** — 不说"你应该""建议你""推荐你"
- **长度控制** — 50~1200 字，太短没诚意，太长像作文

## 快速开始

### 前置要求

- Node.js 18+
- pnpm 9+（**仅允许 pnpm，禁止 npm 或 yarn**）

### 安装

```bash
git clone https://github.com/Lucia-law/echo-music-companion.git
cd echo-music-companion
pnpm install
```

### 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`：

```env
# LLM API（支持 OpenAI 兼容 API）
LLM_API_KEY=your-api-key-here
LLM_API_BASE=https://api.deepseek.com/v1
LLM_MODEL=deepseek-v4-flash

# Supabase（回响之地数据存储）
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# 搜索 API（可选，增强歌曲链接解析）
SEARCH_API_KEY=
SEARCH_API_BASE=

# 服务器配置
PORT=5000
HOSTNAME=localhost
```

### 数据库初始化

在 Supabase 的 SQL Editor 中执行 `supabase/schema.sql`，创建以下表：

- **spaces** — 回响空间（空间名 + 密码哈希）
- **records** — 听歌记录（歌曲信息 + AI 回应 + 用户倾诉 + 情绪标签）

### 启动开发服务器

```bash
pnpm dev
```

访问 `http://localhost:5000`。

### 构建与部署

```bash
pnpm build
pnpm start
```

## 设计决策

### 为什么不用评论区

最初考虑过抓取音乐平台的评论区，但评论区是「别人的故事」。回响想做的是「你的故事」。AI 的角色不是搬运热评，而是认真读完歌词后，像一个有感受力的朋友一样回应你。

### 为什么禁止 emoji 和音乐术语

emoji 让文字变得轻飘飘，音乐术语让对话变得像在写乐评。回响追求的是一种「认真但不端着」的语感——像深夜发的长消息，不像公众号文章。

### 为什么用守卫重试

LLM 有时候会跑偏：突然蹦出一个 emoji，或者开始"建议你听听xxx的其他作品"。守卫机制会在生成后自动检测这些模式，不合格就重试。最多重试 3 次，确保输出符合「朋友聊歌」的调性。

### 为什么是星云而不是列表

听歌的记录不应该像 Excel 表格。每首歌是一颗星，有大有小、有亮有暗。你不需要记住精确的日期，只需要知道「那颗比较亮的星，是那天深夜循环的那首」。
